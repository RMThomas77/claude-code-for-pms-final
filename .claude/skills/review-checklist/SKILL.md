# Review checklist

Run the same eight checks, in this order, on whatever brief the user points at. Read the whole brief first, then report. Do not edit the brief; report findings and suggest wording the user can paste in.

## The eight checks

1. **Owner named.** Does the brief name who owns it? A specific person or team counts. "TBD", a department, or no mention doesn't.
2. **Success measure.** Does it say how we'll know it worked? Look for a metric, a target or direction, and when it will be measured. A goal with no way to check it fails.
3. **Scope matches.** Compare the scope stated at the start (goals, in/out of scope, the problem being solved) with the scope at the end (recommendation, deliverables, next steps, follow-ups). Flag anything that appears at the end but wasn't in the opening scope, and anything promised at the start that never gets delivered.
4. **Problem before fix.** Does the brief explain the problem before it proposes a solution? Check the order and that the problem stands on its own, with evidence, rather than being implied by the fix.
5. **Open questions posed.** Does it list questions that may not have been answered: unknowns, assumptions, things still to confirm? If there are none, say whether that looks credible for this brief, and name the likeliest unanswered questions you can see.
6. **How long it's been present.** Does it say how long the issue has existed, or when it started? A date, release, or duration counts ("since 4.2", "about six weeks"). "Recently" doesn't.
7. **Priority stated.** Does it say how important or urgent the issue is, and why? A rating with no reasoning is Partial. Look for the impact (who is affected, how many, how badly) behind the priority.
8. **How the issue became known.** Does it say where the issue came from: users, internal reports, support tickets, interviews, data, monitoring, and so on? Several sources are better than one. Flag a claim that rests on a single source, or a source that isn't named.

## How to report

Start with a one-line verdict: ready to go further, or not yet.

Then a table, one row per check:

| Check | Result | Evidence |
|---|---|---|

- Result is **Pass**, **Partial** or **Fail**.
- Evidence quotes or points to the section that supports the result. For a Fail, say what's missing.

After the table, list the fixes needed, most important first, each with a suggested line or two the user can paste in. Keep it to the eight checks. Mention anything else you noticed in a single closing line, not as extra checks.

If no brief is named, ask which file to review. If the brief is long, still check all eight points against the whole document, not just the opening.
